<Callout variant="important">
  Agent Control and New Relic Control are **generally available** for Kubernetes. Support for Linux and Windows hosts is in **public preview** program, pursuant to our [pre-release policies](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy).
</Callout>

Agent Control is installed through the **guided install** in the New Relic UI. The guided install generates a platform-specific install command pre-filled with your credentials and fleet configuration. Select your environment below for step-by-step instructions.

<Callout variant="tip">
  For automating Agent Control setup across large-scale infrastructure, see [Set up Agent Control with Terraform](/docs/infrastructure-as-code/terraform/agent-control).
</Callout>

## Before you begin

Verify your environment meets the requirements for Agent Control. For detailed requirements, see [Agent Control overview](/docs/new-relic-control/agent-control/overview/#requirements-and-compatibility).

| Requirement | Kubernetes | Linux hosts | Windows hosts |
| :--- | :--- | :--- | :--- |
| New Relic license key | ✅ Required | ✅ Required | ✅ Required |
| Fleet in Fleet Control | ✅ Required (any type) | ✅ Required (Host - Linux) | ✅ Required (Host - Windows) |
| Helm 3+ | ✅ Required | — | — |
| Auth Domain Manager role | ✅ Required | ✅ Required | ✅ Required |
| Administrator / root privileges | — | ✅ Required | ✅ Required |
| PowerShell 5.0+ | — | — | ✅ Required |
| Outbound HTTPS (port 443) | ✅ Required | ✅ Required | ✅ Required |
| Port 51200 available | — | — | ✅ Required |

<Callout variant="caution" title="Existing instrumentation">
  Agent Control does not automatically migrate existing agent installations. If agents are already running on your cluster or host, uninstall them first, then manage them through Agent Control. See [Migrate existing instrumentation](/docs/new-relic-control/agent-control/reinstrumentation) for guidance.
</Callout>

## Install Agent Control

    <TabsPageItem id="install-k8s">

<Steps>
  <Step>
    **Start the guided install.** In New Relic, go to **Integrations & Agents**, then search for and click **Install Agent Control**. Ensure the correct account is selected.

    <img
      title="Agent Control guided install"
      alt="Screenshot of the guided install tasks for Agent Control"
      src="/images/agent-control-guided-install.webp"
    />
  </Step>

  <Step>
    **Select or create a fleet.** The guided install requires a fleet. Select an existing fleet or create one of type **"Kubernetes"** during this step.
  </Step>

  <Step>
    **Download and run the Helm command.** The guided install generates a `values.yaml` file and a `helm upgrade --install` command pre-filled with your credentials. Download the file and run the command:

    ```shell
    helm upgrade --install agent-control-bootstrap -n newrelic \
      newrelic/agent-control-bootstrap --create-namespace \
      --values my_values.yaml
    ```

    <Callout variant="important" title="Credential expiration">
      The installation credentials generated by the guided install expire after **12 hours**. If your installation fails with `Expired client secret`, generate new credentials by restarting the guided install. Do not add agent-specific chart values to `my_values.yaml` — manage agent configuration through Fleet Control instead.
    </Callout>
  </Step>

  <Step>
    **Verify the installation.** Check that Agent Control and its managed agent pods are running:

    ```shell
    kubectl get pods -n newrelic-agent-control    # Agent Control pods
    kubectl get pods -n newrelic                  # Managed agent pods
    ```

    Agent Control installs its pods in the `newrelic-agent-control` namespace. Managed agents run in the `newrelic` namespace.
  </Step>

  <Step>
    **Confirm in Fleet Control.** In New Relic, go to **Fleet Control** and select your fleet. In the **Entities** table, confirm your Kubernetes cluster appears and its instrumentation status is **healthy**.

    <!-- TODO: screenshot of Fleet Control showing connected Kubernetes cluster after install -->
  </Step>
</Steps>

<CollapserGroup>
  <Collapser id="existing-flux" title="Using an existing Flux installation">
    By default, the Agent Control Helm chart uses an embedded instance of [Flux CD](https://fluxcd.io/) to manage the lifecycle of agents in Kubernetes. If your organization already uses **Flux v2** for GitOps, you can configure Agent Control to use your existing installation instead.

    #### Requirements

    Your existing Flux installation must meet these requirements:
    - **Flux v2** or higher
    - **Helm Controller** with the `HelmRelease` CRD (`helm.toolkit.fluxcd.io/v2`)
    - **Source Controller** with the `HelmRepository` CRD (`source.toolkit.fluxcd.io/v1`)
    - Configured to watch the namespace where Agent Control will be installed (or all namespaces)

    #### Configuration

    In your `values.yaml`, disable the bundled Flux components:

    ```yaml
    global:
      cluster: "<YOUR_CLUSTER_NAME>"
      licenseKey: "<YOUR_LICENSE_KEY>"

    # Disable the embedded Flux instance
    agentControlCd:
      enabled: false

    agentControlDeployment:
      chartValues:
        # ... other configurations ...
    ```

    #### Permissions for external Flux

    Your existing Flux Service Account needs permissions to deploy New Relic resources. Choose one of:

    - **Cluster Admin (recommended):** Ensure your Flux instance runs with `cluster-admin` privileges — the standard for the Flux community chart.
    - **Least Privilege:** Create a specific `ClusterRole` with the minimum permissions. Below is an example:

    ```yaml
    apiVersion: rbac.authorization.k8s.io/v1
    kind: ClusterRole
    metadata:
      name: external-flux-agent-control-role
    rules:
      # Permissions required by Flux to operate Agent Control components
      - apiGroups: ["apiextensions.k8s.io"]
        resources: ["customresourcedefinitions"]
        verbs: ["get"]
      - apiGroups: ["coordination.k8s.io"]
        resources: ["leases"]
        verbs: ["get", "create", "update"]
      - apiGroups: ["rbac.authorization.k8s.io"]
        resources: ["clusterroles", "rolebindings"]
        verbs: ["get", "create", "delete"]
      - apiGroups: [""]
        resources: ["configmaps"]
        verbs: ["watch"]
      - apiGroups: [""]
        resources: ["events"]
        verbs: ["create", "patch"]
      - apiGroups: [""]
        resources: ["namespaces"]
        verbs: ["create"]
      - apiGroups: [""]
        resources: ["serviceaccounts"]
        verbs: ["get", "create", "delete"]
      - apiGroups: [""]
        resources: ["services"]
        verbs: ["get", "create"]
      - apiGroups: ["apps"]
        resources: ["deployments"]
        verbs: ["create"]
      - apiGroups: ["autoscaling"]
        resources: ["horizontalpodautoscalers"]
        verbs: ["get", "create"]
      - apiGroups: ["batch"]
        resources: ["jobs"]
        verbs: ["get", "list", "watch", "create", "delete"]

      # Permissions required by Agent Control logic
      - apiGroups: ["helm.toolkit.fluxcd.io", "newrelic.com", "source.toolkit.fluxcd.io"]
        resources: ["*"]
        verbs: ["*"]
      - apiGroups: [""]
        resources: ["secrets"]
        verbs: ["*"]
      - apiGroups: [""]
        resources: ["configmaps"]
        verbs: ["get", "list", "create", "patch", "update", "delete", "deletecollection"]
      - apiGroups: [""]
        resources: ["namespaces"]
        verbs: ["get"]
      - apiGroups: ["apps"]
        resources: ["daemonsets", "deployments", "statefulsets"]
        verbs: ["get", "list", "watch"]
    ```

    <Callout variant="important">
      Agent permissions may change as new features or agents are added. You are responsible for maintaining these permissions in your custom role.
    </Callout>

    #### Support boundaries

    When using an external Flux installation, New Relic support covers Agent Control software only (generating valid configuration manifests). Shared responsibilities:

    - **New Relic:** Ensures Agent Control correctly interacts with the New Relic backend and generates valid `HelmRelease` and `HelmRepository` definitions.
    - **You:** Responsible for the health, version maintenance, networking, and troubleshooting of your own Flux installation.
  </Collapser>
</CollapserGroup>

<Steps>
  <Step>
    **Start the guided install.** In New Relic, go to **Integrations & Agents**, then search for and click **Install Agent Control**. Ensure the correct account is selected.
  </Step>

  <Step>
    **Select or create a fleet.** Select an existing fleet of type **"Host - Linux"**, or create one during this step.
  </Step>

  <Step>
    **Run the install command.** The guided install generates a CLI install command for your account. Copy and run it on your Linux host. To enable verbose logging during the install, append `--debug` to the command.

    If the installation fails with `Error creating an identity`, ensure your user key belongs to a platform user with the [All product admin](https://docs.newrelic.com/docs/accounts/accounts-billing/new-relic-one-user-management/user-management-concepts/#standard-roles) role.
  </Step>

  <Step>
    **Verify the installation.** Check that the Agent Control service is running:

    ```bash
    sudo systemctl status newrelic-agent-control
    ```

    A healthy service shows `Active: active (running)`. If the service is in `failed` or `stopped` state, check the logs:

    ```bash
    journalctl -u newrelic-agent-control -n 50
    ```

    If no insights are available, see [Enable debug logging](/docs/new-relic-control/agent-control/troubleshooting/#debug).
  </Step>

  <Step>
    **Confirm in Fleet Control.** In New Relic, go to **Fleet Control** and select your fleet. In the **Entities** table, confirm your Linux host appears and its status is **healthy**.

  </Step>
</Steps>

    <TabsPageItem id="install-windows">

<Callout variant="important" title="Windows installation notes">
  Agent Control for Windows is installed using a PowerShell script (MSI installers are not available). You must run this script with Administrator privileges.

  **Fleet type:** You must select or create a fleet of type **"Host - Windows"** during the guided install. Using any other fleet type will cause failures.

  **Minimum agent versions:** Ensure you select compatible versions when deploying agents through Fleet Control:
  - Infrastructure Agent: version 1.71.0 or higher
  - NRDOT (OpenTelemetry Collector): version 1.5.0 or higher
</Callout>

<CollapserGroup>
  <Collapser id="windows-prereq" title="Pre-installation checklist">
    Before running the guided install, verify:

    - [ ] **Administrator privileges** — Right-click PowerShell and select "Run as Administrator"
    - [ ] **PowerShell 5.0+** — Verify: `$PSVersionTable.PSVersion`
    - [ ] **Port 51200 available** — Verify: `netstat -ano | findstr :51200` (no output means available)
    - [ ] **Infrastructure Agent removed** — Verify: `Get-Service -Name newrelic-infra -ErrorAction SilentlyContinue`. If it returns a service, [uninstall it first](/docs/new-relic-control/agent-control/reinstrumentation/#windows-migration). APM agents can remain.
    - [ ] **Fleet of type "Host - Windows"** created in Fleet Control
    - [ ] **Outbound HTTPS** to `download.newrelic.com` — Test: `Test-NetConnection -ComputerName download.newrelic.com -Port 443`
    - [ ] **Antivirus exclusions** configured for:
      - `C:\Program Files\New Relic\newrelic-agent-control\`
      - `C:\ProgramData\New Relic\newrelic-agent-control\`

    <Callout variant="caution" title="Antivirus and security software">
      Windows Defender or third-party antivirus software may block Agent Control from running as a service. Add the directories above to your antivirus exclusions before installation. If Agent Control fails to start as a service but runs from the command line, antivirus interference is the most likely cause.
    </Callout>
  </Collapser>
</CollapserGroup>

<Steps>
  <Step>
    **Start the guided install.** In New Relic, go to **Integrations & Agents**, then search for and click **Install Agent Control**. Ensure the correct account is selected.
  </Step>

  <Step>
    **Select or create a fleet.** Select an existing fleet of type **"Host - Windows"**, or create one during this step. Using the wrong fleet type will cause the installation to fail.
  </Step>

  <Step>
    **Run the PowerShell install script.** The guided install generates a PowerShell script for your account. Open PowerShell as Administrator and run the provided script.

    The script downloads and installs Agent Control, registers it as a Windows service, and creates the configuration file at:
    ```
    C:\Program Files\New Relic\newrelic-agent-control\local-data\agent-control\local_config.yaml
    ```
  </Step>

  <Step>
    **Verify the installation.** Check the service status and health endpoint:

    ```powershell
    Get-Service -Name newrelic-agent-control
    Invoke-WebRequest -Uri "http://localhost:51200/status" -UseBasicParsing
    ```

    Expected: service `Status : Running` and a JSON health response with `"healthy": true`.

    If the service is stopped or the health endpoint doesn't respond, see [Windows hosts troubleshooting](/docs/new-relic-control/agent-control/troubleshooting/#windows-hosts-troubleshooting).
  </Step>

  <Step>
    **Confirm in Fleet Control.** In New Relic, go to **Fleet Control** and select your fleet. In the **Entities** table, confirm your Windows host appears within 1–2 minutes. Then deploy agents (Infrastructure Agent, NRDOT) through Fleet Control to begin collecting telemetry.

    <!-- TODO: screenshot of Fleet Control showing connected Windows host after install -->

    <Callout variant="tip">
      Agent Control is a supervisor — it does not collect telemetry itself. To see infrastructure metrics or logs in New Relic, deploy agents through Fleet Control after installation.
    </Callout>
  </Step>
</Steps>

#### Windows directory structure

Agent Control creates the following directories on Windows:

**Program Files (executables):**
```
C:\Program Files\New Relic\newrelic-agent-control\
├── newrelic-agent-control.exe
├── uninstall.ps1
└── local-data\
    └── agent-control\
        └── local_config.yaml
```

**ProgramData (runtime data):**
```
C:\ProgramData\New Relic\newrelic-agent-control\
├── fleet-data\agent-control\remote_config.yaml
├── logs\newrelic-agent-control.log
├── filesystem\
└── packages\
```

<Callout variant="tip" title="Log location">
  Log files use date suffixes, for example `newrelic-agent-control.log.2026-02-09-11`. View recent logs:

  ```powershell
  Get-ChildItem "C:\ProgramData\New Relic\newrelic-agent-control\logs\" -Filter "newrelic-agent-control.log.*" | Sort-Object LastWriteTime -Descending | Select-Object -First 1 | Get-Content -Tail 100
  ```
</Callout>

## Credential expiration (Kubernetes) [#credential-expiration]

New Relic Control uses system identities — non-human identities that authenticate trust between Agent Control and Fleet Control. During the guided install, the first system identity is created using client credentials embedded in the Helm chart. **These credentials expire after 12 hours.**

When they expire, the Helm chart fails to authenticate with Fleet Control:

```
Error getting system identity auth token. The API endpoint returned 400: Expired client secret.
```

To fix this, update the Helm chart with new credentials:

```yaml
global:
  cluster: "cluster-name"
  licenseKey: "*************************"
agentControlDeployment:
  chartValues:
    systemIdentity:
      organizationId: "00000000-0000-0000-0000-000000000000"
      parentIdentity:
        clientId: "CLIENT_ID"
        clientSecret: "CLIENT_SECRET"
    config:
      fleet_control:
        fleet_id: "SAMPLE_FLEET_ID"
      agents:
        ...
```

## Uninstall Agent Control [#uninstall]

<Tabs>
  <TabsBar>
    <TabsBarItem id="uninstall-k8s">Kubernetes</TabsBarItem>
    <TabsBarItem id="uninstall-linux">Linux hosts</TabsBarItem>
    <TabsBarItem id="uninstall-windows">Windows hosts</TabsBarItem>
  </TabsBar>

  <TabsPages>
    <TabsPageItem id="uninstall-k8s">

<Steps>
  <Step>
    List all installed releases to identify the Agent Control release:

    ```shell
    helm list --all-namespaces
    ```
  </Step>

  <Step>
    Uninstall Agent Control, replacing `<RELEASE>` and `<NAMESPACE>` with your values:

    ```shell
    helm uninstall <RELEASE> -n <NAMESPACE>
    ```

    For example:

    ```shell
    helm uninstall agent-control-bootstrap -n newrelic
    ```
  </Step>
</Steps>

    </TabsPageItem>

    <TabsPageItem id="uninstall-linux">

<Callout variant="important">
  The uninstall process may leave behind configuration and data files. After uninstalling, review and remove these directories if needed:
  - `/etc/newrelic-agent-control`
  - `/var/lib/newrelic-agent-control`
  - `/usr/bin/newrelic-cli` (New Relic CLI binary)
</Callout>

    <TabsPageItem id="uninstall-windows">

<Callout variant="important">
  The uninstall script removes the Agent Control service and executable. Configuration files may remain. After uninstalling, remove these directories if you want a clean removal:
  - `C:\Program Files\New Relic\newrelic-agent-control\`
  - `C:\ProgramData\New Relic\newrelic-agent-control\`
</Callout>

<Steps>
  <Step>
    Open PowerShell with Administrator privileges.
  </Step>

  <Step>
    Navigate to the Agent Control directory and run the uninstall script:

    ```powershell
    cd "C:\Program Files\New Relic\newrelic-agent-control"
    .\uninstall.ps1
    ```

    The script stops the service, removes the service registration, and deletes the executable.
  </Step>

  <Step>
    (Optional) Remove remaining configuration and data directories:

    ```powershell
    Remove-Item -Path "C:\Program Files\New Relic\newrelic-agent-control" -Recurse -Force
    Remove-Item -Path "C:\ProgramData\New Relic\newrelic-agent-control" -Recurse -Force
    ```
  </Step>
</Steps>
