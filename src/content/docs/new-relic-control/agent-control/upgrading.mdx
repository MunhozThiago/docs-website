This page covers two distinct upgrade concerns:

- **Upgrade Agent Control itself** — Update the supervisor binary. Agent Control is a managed service with its own version and release cycle.
- **Upgrade managed agents** — Update the agents Agent Control supervises (Infrastructure Agent, NRDOT, Fluent Bit, and others). This is done entirely through Fleet Control.

<Callout variant="tip" title="Version compatibility">
  Agent Control is backward compatible with managed agent versions. You can upgrade Agent Control independently from your managed agents, and you can upgrade managed agents independently from each other. There is no required upgrade order.
</Callout>

## Upgrade Agent Control [#upgrade-agent-control]

Agent Control is a managed service with its own version and release cycle. Upgrading it gives you new capabilities, bug fixes, and performance improvements while leaving your managed agents and their configurations untouched.

  <TabsBar>
    <TabsBarItem id="upgrade-k8s">Kubernetes</TabsBarItem>
    <TabsBarItem id="upgrade-linux">Linux hosts</TabsBarItem>
    <TabsBarItem id="upgrade-windows">Windows hosts</TabsBarItem>
  </TabsBar>

  <TabsPages>
    <TabsPageItem id="upgrade-k8s">

On Kubernetes, Agent Control can update itself remotely through Fleet Control — no cluster access required. The process is the same as upgrading any managed agent.

<Steps>
  <Step>
    In Fleet Control, open the configuration for your Agent Control deployment.
  </Step>

  <Step>
    Update the `chart_version` field to the new desired version:

    ```yaml
    chart_version: "0.6.0"  # Replace with the target version
    ```
  </Step>

  <Step>
    Save and deploy the configuration.

    This triggers a rolling update of the Agent Control pods on your cluster. Kubernetes built-in health checks ensure the new version is healthy before the old one is terminated.
  </Step>
</Steps>

<CollapserGroup>
  <Collapser id="rollback-k8s" title="Rollback Agent Control on Kubernetes">
    If an upgrade causes issues, set the `chart_version` back to the previous version in Fleet Control and redeploy.

    Alternatively, use Helm directly:

    ```shell
    # List recent Helm releases to find the revision to roll back to
    helm history agent-control-bootstrap -n newrelic

    # Roll back to the previous revision
    helm rollback agent-control-bootstrap -n newrelic
    ```
  </Collapser>
</CollapserGroup>

    </TabsPageItem>

    <TabsPageItem id="upgrade-linux">

Upgrade Agent Control on Linux using your distribution's package manager:

<Tabs>
  <TabsBar>
    <TabsBarItem id="upgrade-debian">Debian, Ubuntu</TabsBarItem>
    <TabsBarItem id="upgrade-suse">SLES</TabsBarItem>
    <TabsBarItem id="upgrade-redhat">Amazon Linux, CentOS, RHEL</TabsBarItem>
  </TabsBar>

  <TabsPages>
    <TabsPageItem id="upgrade-debian">
      ```bash
      sudo apt-get update && sudo apt-get install --only-upgrade newrelic-agent-control -y
      ```
    </TabsPageItem>

    <TabsPageItem id="upgrade-suse">
      ```bash
      sudo zypper -n update newrelic-agent-control
      ```
    </TabsPageItem>

    <TabsPageItem id="upgrade-redhat">
      ```bash
      sudo yum update newrelic-agent-control -y
      ```
    </TabsPageItem>
  </TabsPages>
</Tabs>

<CollapserGroup>
  <Collapser id="rollback-linux" title="Rollback Agent Control on Linux">
    To roll back to a previous version, install the specific version explicitly:

    **Debian / Ubuntu:**
    ```bash
    sudo apt-get install newrelic-agent-control=<previous-version> -y
    ```

    **Amazon Linux / CentOS / RHEL:**
    ```bash
    sudo yum downgrade newrelic-agent-control-<previous-version> -y
    ```

    **SLES:**
    ```bash
    sudo zypper install --oldpackage newrelic-agent-control-<previous-version>
    ```

    After downgrading, restart the service:

    ```bash
    sudo systemctl restart newrelic-agent-control
    ```
  </Collapser>
</CollapserGroup>

    </TabsPageItem>

    <TabsPageItem id="upgrade-windows">

Agent Control on Windows is upgraded by re-running the installation script provided in the guided install. The script downloads the new version and replaces the existing executable while preserving your configuration files.

<Steps>
  <Step>
    Open PowerShell with Administrator privileges.
  </Step>

  <Step>
    Run the installation script from the guided install for the new version. The script automatically detects the existing installation and upgrades it in place.
  </Step>

  <Step>
    Verify the upgrade by checking the service status and health endpoint:

    ```powershell
    Get-Service -Name newrelic-agent-control
    Invoke-WebRequest -Uri "http://localhost:51200/status" -UseBasicParsing
    ```
  </Step>
</Steps>

<CollapserGroup>
  <Collapser id="rollback-windows" title="Rollback Agent Control on Windows">
    To roll back, re-run the installation script for the previous version from the guided install. The script replaces the current executable while preserving your configuration files.

    After re-running the script, verify the service is running:

    ```powershell
    Get-Service -Name newrelic-agent-control
    ```
  </Collapser>
</CollapserGroup>

    </TabsPageItem>
  </TabsPages>
</Tabs>

## Start, stop, and restart Agent Control [#start-stop-restart]

<Callout variant="tip">
  On Kubernetes, Agent Control pods are managed by a Helm release and reconciled by Flux. To restart Agent Control on Kubernetes, delete the pod and let Kubernetes recreate it: `kubectl delete pod <agent-control-pod-name> -n newrelic-agent-control`.
</Callout>

<Tabs>
  <TabsBar>
    <TabsBarItem id="service-linux">Linux</TabsBarItem>
    <TabsBarItem id="service-windows">Windows</TabsBarItem>
  </TabsBar>

  <TabsPages>
    <TabsPageItem id="service-linux">
      Agent Control uses `systemd` on Linux. Select `start`, `stop`, `restart`, or `status` as needed:

      ```shell
      sudo systemctl start newrelic-agent-control
      sudo systemctl stop newrelic-agent-control
      sudo systemctl restart newrelic-agent-control
      sudo systemctl status newrelic-agent-control
      ```
    </TabsPageItem>

    <TabsPageItem id="service-windows">
      Run these commands in PowerShell with Administrator privileges:

      ```powershell
      Start-Service -Name newrelic-agent-control
      Stop-Service -Name newrelic-agent-control
      Restart-Service -Name newrelic-agent-control
      Get-Service -Name newrelic-agent-control
      ```
    </TabsPageItem>
  </TabsPages>
</Tabs>

## Upgrade managed agents [#upgrade-managed-agents]

Managed agents are upgraded through Fleet Control — you never need to touch individual machines. Update the desired agent version in your fleet configuration and deploy. Agent Control detects the change and performs a non-disruptive rolling update, ensuring the new version is healthy before replacing the old one.

1. Navigate to the configuration for your fleet in Fleet Control.
2. Locate the agent you want to update (for example, `infrastructure`) and change the `chart_version` value.
3. Save and deploy the updated configuration.

Agent Control propagates the change to every cluster and host in the fleet. For fleets with many environments, this means a single config change rolls out your update everywhere simultaneously.

### Example: Upgrade the infrastructure agent

```yaml
# Remote configuration for the infrastructure agent
infrastructure:
  chart_version: "5.0.110"  # Change this to the new version
  chart_values:
    newrelic-infrastructure:
      enableProcessMetrics: true
```
