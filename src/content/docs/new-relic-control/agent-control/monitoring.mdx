<Callout variant="important">
  Agent Control and New Relic Control are now **generally available** for Kubernetes! Support for Linux hosts and Windows hosts is also in **public preview** program, pursuant to our [pre-release policies](/docs/licenses/license-information/referenced-policies/new-relic-pre-release-policy).
</Callout>

Agent Control gives you two levels of visibility into your instrumentation fleet:

- **Fleet Control UI** — Your primary tool for fleet-wide visibility. See what agents are running across every cluster and host in your fleet, the agent version in use on each, current health status, and the configuration they received — without connecting to individual machines. Navigate to **[Fleet Control](/docs/new-relic-control/fleet-control/overview)** in the New Relic UI to access the fleet health dashboard.

- **Direct inspection commands** — For diagnosing a specific cluster or host, verifying that a configuration change was applied, or investigating an agent that appears unhealthy in Fleet Control. The commands in this page let you inspect the live state of Agent Control and every agent it manages, directly on the machine.

<Callout variant="tip" title="Centralized monitoring (coming soon)">
  New Relic Control will soon provide a centralized monitoring experience inside the New Relic UI, including direct links from fleet health status to each agent's entity dashboard. This experience will be available for all supported environments.
</Callout>

### Check pod status and logs

Use standard Kubernetes commands to verify that Agent Control and its managed agent pods are running as expected.

```shell
# Check Agent Control supervisor pods
kubectl get pods -n newrelic-agent-control

# Check managed agent pods (typically in the 'newrelic' namespace)
kubectl get pods -n newrelic

# View logs for the Agent Control supervisor
kubectl logs <agent-control-pod-name> -n newrelic-agent-control

# Follow logs in real time
kubectl logs -f <agent-control-pod-name> -n newrelic-agent-control
```

### Use the local status endpoint

Agent Control exposes a local HTTP status endpoint that provides a health check of both the supervisor and all its managed agents.

<Steps>
  <Step>
    **Forward the port.** In a terminal, run:

    ```shell
    kubectl port-forward <agent-control-pod-name> 51200:51200 -n newrelic-agent-control
    ```
  </Step>

  <Step>
    **Query the status endpoint.** In a new terminal, run:

    ```shell
    curl localhost:51200/status
    ```
  </Step>
</Steps>

For the JSON response format and field descriptions, see [Status response structure](#status-response-structure) below.

### Check service status

Use `systemctl` to verify that the Agent Control service is running:

```bash
sudo systemctl status newrelic-agent-control
```

A healthy service shows `Active: active (running)`. If the service is in `failed` or `inactive` state, see [Troubleshooting](/docs/new-relic-control/agent-control/troubleshooting/#linux-hosts-troubleshooting).

### Check service logs

View Agent Control logs using `journalctl`:

```bash
# View recent logs
journalctl -u newrelic-agent-control --no-pager -n 100

# Follow logs in real time
journalctl -u newrelic-agent-control -f
```

Log files are also written to disk at:

```
/var/log/newrelic-agent-control/newrelic-agent-control.log
```

### Use the local status endpoint

Agent Control on Linux exposes the same HTTP status endpoint as Kubernetes.

```bash
curl localhost:51200/status
```

For field descriptions, see [Status response structure](#status-response-structure) below.

<Callout variant="tip">
  If `curl` returns a connection refused error, verify the service is running with `systemctl status newrelic-agent-control` and check the logs for startup errors.
</Callout>

    </TabsPageItem>

### Check service status

Use PowerShell to verify the Agent Control service status:

```powershell
Get-Service -Name newrelic-agent-control
```

Expected output when healthy:

```
Status   Name                     DisplayName
------   ----                     -----------
Running  newrelic-agent-control   New Relic Agent Control
```

If the service shows `Stopped`, see [Windows hosts troubleshooting](/docs/new-relic-control/agent-control/troubleshooting/#windows-hosts-troubleshooting).

### Check service logs

Agent Control writes structured logs to:

```
C:\ProgramData\New Relic\newrelic-agent-control\logs\
```

To collect all log files into a single output file for investigation:

```powershell
Get-ChildItem "C:\ProgramData\New Relic\newrelic-agent-control\logs\" -Filter "newrelic-agent-control.log*" |
  Sort-Object LastWriteTime -Descending |
  ForEach-Object { Get-Content $_.FullName } |
  Out-File -FilePath "$env:USERPROFILE\Desktop\agent-control-debug.log"
```

### Use the local status endpoint

Agent Control on Windows exposes the same HTTP status endpoint.

```powershell
Invoke-WebRequest -Uri "http://localhost:51200/status" -UseBasicParsing | Select-Object -ExpandProperty Content
```

For field descriptions, see [Status response structure](#status-response-structure) below.

<Callout variant="tip">
  If the request fails, verify that port 51200 is not blocked by the local Windows Firewall or antivirus software.
</Callout>

## Status response structure

The `/status` endpoint returns a JSON response with the health of the supervisor and all managed agents. The response format is identical across Kubernetes, Linux, and Windows environments.

<CollapserGroup>
  <Collapser id="status-json" title="Example status response">
    ```json
    {
      "supervisor": {
        "status": "healthy",
        "version": "0.5.2",
        "uptime": "3h42m"
      },
      "agents": [
        {
          "name": "infrastructure",
          "agent_type": "newrelic/com.newrelic.infrastructure:0.1.0",
          "status": "healthy",
          "chart_version": "5.0.109",
          "last_reconciled": "2026-03-02T10:15:00Z"
        },
        {
          "name": "logs",
          "agent_type": "newrelic/io.fluentbit:0.1.0",
          "status": "healthy",
          "chart_version": "1.25.1",
          "last_reconciled": "2026-03-02T10:15:00Z"
        }
      ]
    }
    ```

    | Field | Description |
    | :--- | :--- |
    | `supervisor.status` | Overall health of Agent Control: `healthy`, `degraded`, or `error` |
    | `supervisor.version` | Version of Agent Control currently running |
    | `agents[].name` | Name you assigned to the agent in your fleet configuration |
    | `agents[].agent_type` | The agent type identifier and version |
    | `agents[].status` | Health of this specific agent: `healthy`, `degraded`, `error`, or `unknown` |
    | `agents[].chart_version` | The Helm chart version deployed (Kubernetes only) |
    | `agents[].last_reconciled` | Timestamp of the last Agent Control reconciliation for this agent |
  </Collapser>
</CollapserGroup>

## Inspect individual agents

When Fleet Control shows an agent as unhealthy, at an unexpected version, or not receiving its configuration, use these commands to investigate directly on the affected cluster or host. The `/status` endpoint response (see [Status response structure](#status-response-structure) above) is your fastest way to see the running version and health of every agent in a single call.

<Tabs>
  <TabsBar>
    <TabsBarItem id="agents-k8s">Kubernetes</TabsBarItem>
    <TabsBarItem id="agents-linux">Linux hosts</TabsBarItem>
    <TabsBarItem id="agents-windows">Windows hosts</TabsBarItem>
  </TabsBar>

  <TabsPages>
    <TabsPageItem id="agents-k8s">

Inspect the HelmRelease resources that Flux manages for each agent. The `READY` column indicates whether Flux has successfully deployed the desired version.

```shell
# List all managed agents with version and ready status
kubectl get helmreleases -n newrelic

# Detailed status for a specific agent — shows the chart version, last reconciliation, and any errors
kubectl describe helmrelease <agent-name> -n newrelic
```

A `READY=False` status means Flux was unable to deploy or reconcile the release. The `describe` output includes the reconciliation error and last attempted action.

```shell
# Check that managed agent pods are running
kubectl get pods -n newrelic

# Tail agent pod logs for live diagnostics
kubectl logs -f <agent-pod-name> -n newrelic
```

    </TabsPageItem>

    <TabsPageItem id="agents-linux">

The `/status` endpoint returns the running version and health status for every managed agent. This is the fastest way to verify what's actually installed and running, as opposed to what was requested.

```bash
curl localhost:51200/status
```

Look at the `agents[].agent_type` field to see the running version and `agents[].status` for its health. For deeper diagnostics when an agent is unhealthy, check the agent's own logs:

```bash
# Infrastructure Agent
sudo tail -f /var/log/newrelic-infra/newrelic-infra.log

# NRDOT Collector
journalctl -u nrdot -f
```

To verify the installed package version directly:

```bash
dpkg -l | grep newrelic-infra           # Debian, Ubuntu
rpm -q newrelic-infra                   # Amazon Linux, CentOS, RHEL
zypper se --installed-only newrelic     # SLES
```

    </TabsPageItem>

    <TabsPageItem id="agents-windows">

The `/status` endpoint returns the running version and health status for every managed agent:

```powershell
Invoke-WebRequest -Uri "http://localhost:51200/status" -UseBasicParsing | Select-Object -ExpandProperty Content
```

Look at the `agents[].agent_type` field to see the running version and `agents[].status` for its health. For deeper diagnostics, check the agent's log files:

```powershell
# Infrastructure Agent
Get-Content "C:\ProgramData\New Relic\newrelic-infra\newrelic-infra.log" -Tail 50 -Wait
```

To verify the installed version directly:

```powershell
Get-WmiObject -Class Win32_Product | Where-Object { $_.Name -like "*New Relic Infrastructure*" } | Select-Object Name, Version
```

    </TabsPageItem>

</Tabs>
