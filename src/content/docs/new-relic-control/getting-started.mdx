New Relic Control is an observability management platform that gives you centralized, scalable control over your instrumentation agents and telemetry pipelines — from a single UI, across every environment you operate.

## Why New Relic Control?

As environments grow, the gap between the observability you want and the observability you have tends to widen. Agents drift out of date. Configurations diverge between clusters. A single change to a license key or agent version requires touching hundreds of machines. Teams spend more time managing instrumentation than using it.

New Relic Control closes that gap. It provides a single place to deploy, configure, upgrade, and monitor your entire instrumentation footprint — without SSH access, custom scripts, or per-host automation.

New Relic Control has three components, each addressing a distinct part of the observability management challenge:

<CollapserGroup>
  <Collapser id="agent-control" title="Agent Control — on-host supervisor">
    **Agent Control** is a lightweight supervisor process you install once per Kubernetes cluster or host. It connects to Fleet Control and handles everything from there: deploying agents, applying configurations, performing rolling upgrades, and continuously monitoring health.

    Agent Control supports:
    - **Kubernetes** (GA): Infrastructure Agent, NRDOT, Fluent Bit, Prometheus, eBPF
    - **Linux hosts** (Public Preview): Infrastructure Agent, NRDOT
    - **Windows hosts** (Public Preview): Infrastructure Agent, NRDOT (experimental)

    Agent Control does not collect or send telemetry itself — it only manages the agents that do. There is no additional ingest cost for the supervisor.

    [Learn more about Agent Control →](/docs/new-relic-control/agent-control/overview)
  </Collapser>

  <Collapser id="fleet-control" title="Fleet Control — centralized management UI">
    **Fleet Control** is the New Relic UI where you manage your entire Agent Control deployment. From Fleet Control you can:

    - Organize clusters and hosts into **fleets** (logical groups with a shared configuration)
    - Deploy agents to all members of a fleet with a single configuration change
    - Monitor the health of every agent across every environment from one dashboard
    - Roll out upgrades incrementally and roll back if needed

    Fleet Control is the source of truth for your agent configuration. When you change a setting in Fleet Control, Agent Control on every affected machine converges to the new state automatically.

    [Learn more about Fleet Control →](/docs/new-relic-control/fleet-control/overview)
  </Collapser>

  <Collapser id="pipeline-control" title="Pipeline Control — data filtering gateway">
    **Pipeline Control** is a data management layer that sits between your agents and New Relic's ingest endpoint. It lets you define rules to filter and discard low-value telemetry — noisy metrics, redundant logs, high-frequency events — before that data reaches the database and drives up ingest costs.

    Pipeline Control is in **general availability (GA)** and works with APM agents. It operates independently of Agent Control — you can use either component without the other.

    [Learn more about Pipeline Control →](/docs/new-relic-control/pipeline-control/overview)
  </Collapser>
</CollapserGroup>

A typical workflow looks like this:

1. **You define the desired state in Fleet Control** — which agents to run, which version, and how they should be configured.
2. **Fleet Control sends that desired state to Agent Control** on each cluster or host via an encrypted, outbound connection.
3. **Agent Control converges your environment** to the desired state — installing, upgrading, or reconfiguring agents as needed.
4. **Agents collect and send telemetry** to New Relic (optionally routed through Pipeline Control for filtering).
5. **Agent Control continuously reports health** back to Fleet Control, so you always have an up-to-date view of your fleet.

## Scope and availability

| Component | GA / Preview | What it manages |
| :--- | :--- | :--- |
| **Agent Control + Fleet Control** (Kubernetes) | ✅ Generally Available | Infrastructure Agent, NRDOT, Fluent Bit, Prometheus, eBPF |
| **Agent Control + Fleet Control** (Linux hosts) | Public Preview | Infrastructure Agent, NRDOT |
| **Agent Control + Fleet Control** (Windows hosts) | Public Preview | Infrastructure Agent, NRDOT (experimental) |
| **Pipeline Control** | ✅ Generally Available | APM agent telemetry (filter before ingest) |

## Key behaviors to know before you start

- **Agent Control starts empty.** No agents are deployed when you install the supervisor. You define what to deploy through Fleet Control after installation.
- **Remote configuration wins.** When both local and remote configuration exist, Fleet Control's remote configuration always takes precedence and overrides local values.
- **No automatic migration.** If agents are already running on a cluster or host, you must uninstall them before installing Agent Control. See [Migrate existing instrumentation](/docs/new-relic-control/agent-control/reinstrumentation).
- **Fleet types matter.** Each environment type (Kubernetes, Linux, Windows) requires a fleet of the matching type. Mixing types causes failures.
